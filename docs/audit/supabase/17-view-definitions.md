# Supabase View Definitions

## Purpose

Capture the complete SQL definitions of all standard PostgreSQL views currently present in the CAFLA application schemas.

View definitions are critical for understanding:

- Derived business logic.
- Cross-schema dependencies.
- Legacy dashboard calculations.
- Development scoring logic.
- Ranking pipelines.
- Tournament statistics.
- Indirect dependencies that may not be visible from application code.

This inventory preserves the actual SQL currently defined in Supabase.

---

## Scope

Schemas included:

- `public`
- `tournaments`
- `development`

Objects included:

- Standard PostgreSQL views (`relkind = 'v'`).

Materialized views are excluded and were audited separately in `03-materialized-views.md`.

---

## Query

```sql
select
  n.nspname as view_schema,
  c.relname as view_name,
  pg_get_viewdef(c.oid, true) as view_definition
from pg_class c
join pg_namespace n
  on n.oid = c.relnamespace
where c.relkind = 'v'
  and n.nspname in ('public', 'tournaments', 'development')
order by
  n.nspname,
  c.relname;
```

## Dependency Significance

Views can form dependency chains such as:

```text
Application
    ↓
View A
    ↓
View B
    ↓
View C
    ↓
Base Table
```

Therefore, a lower-level view may have zero direct application references while still being required by an active higher-level view.

View definitions must be analyzed together with:

- `02-tables-and-views.md`
- `04-columns.md`
- `12-database-dependencies.md`
- Application repository references

---

## Audit Notes

The existence of a view does not prove that the current application uses it.

Likewise, zero direct references in Next.js do not prove that the view is unused.

A removal decision must verify:

1. Direct application references.
2. References from other views.
3. Function references.
4. Trigger/function behavior where relevant.
5. Cron usage.
6. Historical/reporting requirements.
7. Availability of a confirmed replacement.

Particular care should be taken with views whose names suggest older dashboard or ranking architectures.

Naming alone is not sufficient evidence of legacy status.
